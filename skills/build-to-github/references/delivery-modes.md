# 运行、配置与迁移

在选择交付形式、增加手机入口或接手迁移包时读取。

| 形式 | 用户拿到什么 | 实现前核对 |
|---|---|---|
| Skill | 可复用指令和必要工具 | 接收者的 Agent 是否支持 skill、文件、浏览器和所需工具；skill 不包含模型权重 |
| Windows 程序 | 能启动的完整安装包/便携目录 | 入口、架构、运行时和资源一起打包；单独一个 EXE 未必能运行 |
| 本机网页/远程入口 | 浏览器访问本机服务 | 主机运行、网络可达和认证；电脑关闭后服务通常停止 |
| 独立云端 | 托管的前端、后端和持久化服务 | 云端身份、存储、任务执行能力和费用；不能只把本机界面上传 |

## 先核对运行能力

把每个关键需求映射到执行环境：文件持久化、浏览器、模型 API、联网、定时任务、下载、外部写入。托管平台可能没有浏览器或后台任务，API 也可能不提供网页登录能力。缺少能力时选择受支持的集成或保留清楚的未接通状态；不以一个网络链接声称全部桌面功能已经上云。

沿用用户选定的接口/模型。接口协议、鉴权和费用以当前官方文档为准，不缓存某个模型名或版本为通用默认。接收者分别配置自己的凭据；如果本轮需要新凭据，用当前环境的凭据流程。无需新密钥就能完成的开发与 mock 检查继续做。

## 登录与资料

敏感配置经服务端或操作系统凭据存储管理；前端仅显示是否已配置。私人配置按用户身份隔离；共享业务数据按确认的工作区、成员与角色授权开放，访问前核对权限。浏览器会话、MFA、系统凭据与普通模型 API 是不同能力，不能承诺“演示一次后永不验证”。

源码共享、发布 EXE、云端部署和数据迁移分别记录。默认不迁移本机课程、客户、会话和密钥；实际需要迁移时核对范围、备份、导入冲突与回读。发布站点是否私有、接收者能否访问要实际确认，不能从 URL 存在推断公开。

## 可恢复的交付

保留依赖锁、必要原始资产、构建入口和环境变量名称示例，排除真实值。迁移先验证源包哈希，解压到新目录或独立分支，避免覆盖未提交改动。用虚构资料检查安装、启动和核心功能，分别说明哪些真实集成尚未验证。

网站通过对应平台的构建/部署接口发布，保存来源 commit 与部署回执。使用 Sites 时优先读取当前可用的 `sites` skill 和运行时要求，不从历史案例复制站点 ID、用户身份、数据库或密钥。GitHub 源码可获取不代表服务器已经运行。
