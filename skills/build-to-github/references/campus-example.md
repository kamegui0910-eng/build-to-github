# 案例：把课程工作流做成可分享产品

这是截至 2026-11-07 的历史案例，用于理解需求如何落地。它不是新项目的默认需求，也不是要求加载课程业务 skill；其他平台只借用方法。

## 原始需求与交付

| 用户需求 | 转成的可验收行为 | 当时实际状态 |
|---|---|---|
| 按课程获取 syllabus、rubric、教材和作业材料 | 分课程存储；记录原文件、版本、覆盖章节和下载缺口；每项作业绑定具体材料版本 | 已有课程库与资料绑定能力；外部下载仍受账号、权限和材料形式限制 |
| 重复作业章节不同，资料随进度更新 | 按作业章节选择内容；保留旧版本和来源；不足时明确缺口 | 相关提取与版本逻辑有测试；不代表已读取全部教材 |
| 别人使用自己的模型 | 产品内设置接口、模型和凭据，不分享作者的密钥或订阅 | 桌面与云端分别配置；真实付费调用需用户自己的配置 |
| 不再依赖自己启动 Agent | Windows 双击完整便携包后有交互界面、资料库与配置入口 | Windows 便携版已构建；EXE 依赖同包资源 |
| 首次填写学校账号并演示登录 | 本机浏览器按学校档案隔离，有效会话复用，可选加密凭据；学校要求的 MFA 由本人处理 | 桌面模块实现并通过虚构学校页面验证，不代表所有学校都已实测 |
| 手机能用，而且电脑关机也能用 | 独立托管前后端、身份、数据库与文件存储 | 云端独立部署；当时入口仅本人可登录，资料与桌面分开 |
| 定时处理、检测审计和提交 | 分别核对调度宿主、检测网站权限与提交授权/结果 | 云端尚未接入后台定时提交、检测网站或学校网页登录；不宣称整套自动提交完成 |
| 分享给朋友、放 GitHub | 可安装 skill、完整便携包、云端源码、接收者自配说明 | 公开源码和桌面 Release 已发布；不包含学校会话、密码与私人资料 |

## 有用的选择依据

- 先分清“分享指令”“分享程序”“上传模型权重”和“部署运行服务”，避免把不同目标混在同一个安装包里。
- 从已有工程演进，复用登录、课程库和发布能力；云端缺少浏览器时明确差异，没有把本机登录录像当云端自动登录。
- 界面按用户给的配色图实现；开发时检查真实操作链，不以设计图代替运行结果。
- 发布通过显式文件集合、哈希和远端回读确认，凭据只保留在各自运行环境。

## 证据如何描述

当时桌面登录模块有 31 项测试及打包程序的虚构登录页验证；云端有 16 项后端测试、本地 HTTP 接口验收、类型检查和生产构建。部署回执确认云端发布成功，但实际手机视觉交互受环境限制未测，真实学校 API 与付费模型也未在那轮调用。这些结果是不同验证层，不能合成“所有功能已真实跑通”。

## 复用了什么

旧的项目迁移 skill 提供短状态接续、依赖锁、源包哈希和私有配置分离方法；`modularize-project` 提供已有工程的职责边界与按需读取方法。它们仍保留各自范围。本 skill 把这些方法连接到需求、产品形态、验收和 GitHub 交付，没有携带其他项目源码、用户档案或完整聊天。
