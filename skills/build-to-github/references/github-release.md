# GitHub 与打包

发布、生成便携包或迁移接续开发时读取。沿用已有发布工具，下面的 helper 只在缺少可靠预检时使用。

## 发布什么

1. 根据当前任务核对目标账号、仓库、可见性和分支。已有仓库先读元信息与当前 head；新仓库按本轮授权创建。连接器能完成的操作用连接器；没有新建仓库等能力时，使用已登录的 CLI/凭据管理器和官方 API。不得把明文凭据放入命令参数、仓库、包、日志或回执。
2. 显式列出公开文件，包含源码、依赖锁、必要资产、skill 和简短接入说明。运行时数据、`.env` 实值、cookie、会话、真实客户/课程资料、下载缓存和构建目录不默认发布。需要的构建产物放独立 Release，必要的大文件另用受支持存储。
3. 审核清单内容和敏感信息。项目 ID 等私有部署绑定在便携源码中移除或改成环境配置；接收者创建自己的资源。

## 可选的发布快照工具

`scripts/prepare_publication.py` 只有 Python 标准库依赖。准备一个 JSON 文件，内容是审核过的相对**文件**路径数组，然后运行：

```text
python scripts/prepare_publication.py --root PROJECT --allowlist public-files.json --out NEW_OUTPUT_DIRECTORY
```

输出独立的 `source/`、`source.zip` 和 `manifest.json`；清单含每个文件的字节数、SHA256 与 Git blob SHA1。输出目录必须不存在且位于项目之外。工具拒绝路径越界、链接、明显私密路径和部分常见凭据格式，不能代替内容审查，也不能证明没有秘密。它不上传、不授权、不删除源文件。脚本实际参数路径按所安装 skill 的位置解析。

## 写入与回读

使用审核过的快照。多文件优先一次 tree/commit，更新分支时使用工具支持的预期 head/lease 或非强制快进；分支改变就停止、读取新差异，再决定如何合并，不盲目 force。单纯“先读再写”不等于原子 compare-and-swap。

连接器权限不足时准确报告缺少的动作，并采用可用的授权后备方式；不要让用户代做已经可以完成的代码和打包。网络/认证失败保留可交付包和失败原因，依据新证据重试；没有状态变化时不重复发布。新建资源先查同名资源/回执，避免中断后重复创建。

发布后读取远端 commit 和文件，核对清单。Release 附件核对文件名、大小、SHA256；源码更新与 Release 更新分开记录。回执只含仓库 URL、分支、commit、版本、哈希、验证结果和未完成项。需要 Drive 等备份时使用该服务当前 skill，不把备份成功说成 GitHub 发布成功。

## 给使用者的文字

仓库简介用一两句话。README 说明：提供什么、能完成什么、怎样安装/配置、如何启动；只保留影响使用的限制。用户要求双语时中英各一份，保持意思一致。示例配置用占位值，付费模型、浏览器能力和外部账号由接收者配置；不暗示分享了作者的模型订阅。
